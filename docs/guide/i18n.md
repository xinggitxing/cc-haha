# 国际化 (i18n) 支持方案与规范

## 概述

本项目为 TUI (Ink/React) 界面实现中英文双语国际化支持。用户可在设置面板中切换 UI 语言，切换后界面文字立即生效。

## 架构设计

### 分层结构

```
src/i18n/
  index.tsx              # i18n 核心：t() 函数、LocaleProvider、useTranslation()、syncLocaleFromAppState()
  locales/
    en.ts                # 英文词条聚合入口（仅 import + spread）
    zh.ts                # 中文词条聚合入口（仅 import + spread）
    keys/                # 按组件组拆分的独立词条文件
      common.ts          # 通用词条（OK/Cancel/Save 等）
      localePicker.ts    # 语言选择器
      config.ts          # 设置面板
      doctor.ts          # 诊断页面
      resume.ts          # 会话恢复
      repl.ts            # REPL 交互
      tool.ts            # 工具使用消息
      permissions.ts     # 权限对话框（~140 keys）
      scheduledTasks.ts  # 定时任务向导（~60 keys）
      messages.ts        # 消息展示组件
      agents.ts          # Agent 创建/管理
      components.ts      # 核心 UI 组件
```

### 两种调用路径

| 方式 | 使用场景 | 响应式 |
|------|---------|--------|
| `t(key, params?)` | 非 React 代码（工具函数、验证逻辑） | 需组件 remount |
| `useTranslation()` | React 组件内 | 订阅 AppState.locale，自动重渲染 |

### 翻译降级链

```
当前语言翻译 → 英文翻译 → key 字符串本身
```

### 插值语法

```ts
t('key', { param1: 'value', param2: 123 })
// "Hello {param1}, you have {param2} messages" → "Hello value, you have 123 messages"
```

## 添加新组件国际化的步骤

### 1. 判断是否需要国际化

需要 i18n 的字符串：**用户可见的 UI 文本**
- `<Text>` 组件内容、Dialog 标题/副标题
- Select 选项标签/描述、placeholder 文本
- 验证错误消息、状态提示
- 快捷键提示文本

不需要 i18n 的字符串：
- 变量名、函数名、注释
- 内部 key/ID、console.log
- 纯技术性标识（如 `'INSERT'` 模式指示器）

### 2. 创建词条文件

在 `src/i18n/locales/keys/` 下创建新文件，格式：

```ts
export const en = {
  'prefix.key1': 'English text',
  'prefix.key2': 'Hello {name}',
} as const

export const zh: Record<string, string> = {
  'prefix.key1': '中文文本',
  'prefix.key2': '你好 {name}',
}
```

命名规范：
- key 前缀按组件组：`perm.` `agent.` `msg.` `task.` `ui.` 等
- 小写字母 + 点号分隔
- 参数用 `{camelCase}` 包裹

### 3. 注册词条

在 `en.ts` 和 `zh.ts` 中添加：

```ts
import { en as myEn } from './keys/myComponent'
// ...
...myEn,
```

### 4. 在组件中使用

```ts
import { t } from '../../i18n/index.js'
// 或子目录中: import { t } from '../../../i18n/index.js'

// 简单文本
<Text>{t('prefix.key')}</Text>

// 带参数
<Text>{t('prefix.key2', { name: 'foo' })}</Text>
```

### 5. React Compiler memo cache 兼容

如果组件是 React Compiler 编译的（使用 `$` 数组缓存），需要添加 locale 依赖：

```ts
const locale = useAppStateMaybeOutsideOfProvider(s => s.locale)
// 缓存检查加 locale 判断
if ($[n] === Symbol.for("react.memo_cache_sentinel") || ($[n] != null && $[n].l !== locale))
// 缓存值包装
$[n] = { l: locale, v: <Text>{t('key')}</Text> }
// 读取缓存
t1 = $[n] != null ? $[n].v : $[n]
```

## 注意事项

1. **模块级 `t()` vs Hook `useTranslation()`**：React 组件中优先使用 `useTranslation()` 以获得 locale 响应式更新；组件外部（如 validateAgent）使用 `t()`
2. **React Compiler 缓存**：务必检查编译输出文件中的 `$` memo cache，确保 locale 变化时缓存正确失效
3. **中文翻译完整性**：`zh.ts` 使用 `Record<TranslationKey, string>` 类型，编译期保证所有 key 都有中文翻译
4. **词条文件独立存储**：每个组件组的词条存储在独立文件中，避免多人协作时的 Git 冲突

## 搜索替换高危陷阱 ⚠️

批量替换硬编码字符串为 `t('key')` 时，以下 3 类错误会导致启动卡死或运行时异常，**必须逐文件检查**：

### 1. 引号冲突导致语法错误（🚨 启动卡死）

```ts
// ❌ 错误：外层引号被内层 ' 提前闭合
const MESSAGES = ['{t('key')}', "{t('key')}"]   // SyntaxError

// ✅ 正确：直接作为函数调用，不要嵌套引号
const MESSAGES = [t('key')]
```

**根因**：`'{t('key')}'` 中第一个 `'` 闭合了字符串，`{t(` 成为非法表达式，Bun 解析时产生 SyntaxError 导致模块加载死锁。

### 2. `t()` 函数未导入（🚨 启动卡死）

```ts
// ❌ 错误：组件内使用了 t() 但没有 import
import { Text } from '../ink.js'
<Text>{t('key')}</Text>        // ReferenceError: t is not defined

// ✅ 正确：显式导入 t
import { t } from '../i18n/index.js'
import { Text } from '../ink.js'
```

**根因**：变量 `t` 未定义，首次渲染时抛出 ReferenceError，React/Ink 异常处理可能导致进程卡死。

### 3. JSX 属性中的字符串包裹（⚠️ 显示异常）

```ts
// ❌ 错误：JSX 字符串属性不执行表达式
<Dialog title="t('key')" />   // 显示文字 "t('key')"

// ✅ 正确：用 {} 包裹才是函数调用
<Dialog title={t('key')} />

// ❌ 错误：Text 子节点字符串不是表达式
<Text>t('key')</Text>         // 显示文字 "t('key')"

// ✅ 正确：需要 {} 包裹
<Text>{t('key')}</Text>
```

### 4. 变量名被搜索替换误伤（⚠️ 编译错误）

```ts
// ❌ 错误：替换脚本将变量名中的子串也替换了
const [sourceDisplay, sourceSkills] = arr  // 被替换成 source{t('key')}
sourceSkills.map(fn)                        // 被替换成 source{t('key')}.map(fn)

// 导致 SyntaxError：解构模式中不允许函数调用
```

**根因**：全局搜索替换时没有限制匹配范围为字符串字面量，导致变量名也被修改。

### 安全替换流程

```bash
# 1. 只替换字符串字面量，不影响变量名
#    推荐用 AST 工具（如 jscodeshift），而非 sed/全局文本替换

# 2. 替换后逐文件验证：
grep -nE "t\(" src/components/YourFile.tsx    # 确认所有 t() 调用存在
grep -L "import.*i18n" src/components/*.tsx    # 检查缺失 import 的文件

# 3. 验证语法正确性：
bun --evaluate src/components/YourFile.tsx     # 确认无 SyntaxError

# 4. JSX 属性检查：搜索 title="t( 和 label="t( 模式
grep -rnE '="t\(' src/components/ --include="*.tsx"
grep -rnE ">t\('" src/components/ --include="*.tsx"  # 检查 >t(' 裸文本
```

## 质量检查清单（i18n 替换完成后必须执行）

```bash
# 1. 语法检查 — 搜索替换最容易导致 SyntaxError
for f in $(git diff --name-only -- '*.tsx' '*.ts'); do
  bun --evaluate "$f" 2>/dev/null || echo "❌ SyntaxError: $f"
done

# 2. 检查 t() 调用但缺少 import
grep -rln "t(" src/components/ --include="*.tsx" | xargs grep -L "import.*i18n"

# 3. 检查 t() 被字符串包裹（显示异常）
grep -rnE '="t\(' src/ --include="*.tsx"     # title="t(key)" 模式
grep -rnE ">t\('" src/ --include="*.tsx"     # Text 子节点中的裸文本

# 4. 检查变量名被误替换
git diff -- '*.tsx' | grep -E '^\+.*\{t\(' | grep -vE '(Text|title|label|placeholder)='
```
